# Bavaria Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bavaria becomes the fifteenth state freemapper makes maps for: orthophoto, terrain and surface model from the agency's WMS and tiles, buildings from the LoD2 tiles, land use from the files of the Kreise.

**Architecture:** A manifest folder `crates/adapters/de/manifests/bayern/` declares identity, hosts, boundary, seven OSM extracts, credit and preview. The rasters come from a new backend `ldbv` in `crates/adapters/de`, after the pattern of North Rhine-Westphalia. The cadastre has no service, so a code source `LdbvAlkis` downloads files (one CityGML file per 2 km tile, one Shape zip per Kreis), reads them with two new readers in `freemapper-sources` (`citygml`, `shapefile`) and hands the engine the simplified ALKIS schema it knows. Cached files carry the day of the server's `Last-Modified` in their name.

**Tech Stack:** Rust (workspace toolchain), `freemapper-sources` (`height_model`, `float_tiff`, `raster_fetch`, `dates`, new `shapefile` and `citygml`), `freemapper-adapter-api` (`AlkisSource`, `RasterBackend`, `Fetcher`), `quick-xml`, `zip`. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-13-bayern-design.md` (the decisions) and `docs/regions/bayern-reference.md` (every URL, format and size, checked live on 2026-11-13). The scheme itself: `docs/superpowers/specs/2026-11-10-region-adapters-design.md`, `docs/adapters/en.md`.

## Global Constraints

- Adapter id and manifest folder `bayern`; names `Bavaria` (en), `Bayern` (de); provider id, backend name and cache folder `ldbv`; agency label `LDBV`; CRS EPSG:25832 for the whole state; object-id prefix `DEBY`.
- Hosts, exactly: `geoservices.bayern.de`, `download1.bayernwolke.de`. No request of the state goes anywhere else (ADR 0106). `geodaten.bayern.de` and `download2.bayernwolke.de` are not asked by the program.
- Licence `cc-by-4.0`. Credit, exactly: `Geobasisdaten: Bayerische Vermessungsverwaltung – www.geodaten.bayern.de (Daten verändert), Lizenz: CC BY 4.0` (no year). Short credit: `Bayerische Vermessungsverwaltung`.
- Not used on purpose: Hausumringe, the state-wide GeoPackages, the point clouds, the ATKIS WFS, the single trees, the DOP and DOM tiles of 40 cm.
- Requests carry the fixed `User-Agent` and nothing personal. No e-mail address or name of a person in any request, file, fixture or commit.
- No new dependency: the two readers are own code, like the TIFF, zip and XLSX readers.
- Source and technical docs English, user docs German and English, German text says "Bundesland".
- Golden net: only files that list every adapter change; the commit that changes them carries `Golden-Bless: Bavaria added` and is not a `refactor(` commit.
- A counting test (`14` states, list indices, the CSP host list) is updated in the task whose change makes it fail, not earlier.
- Fixtures are cut from fresh answers of the agency (public cadastre and terrain data), a few objects each, and live in `tests/fixtures/` with the prefix `bayern-`.
- Verification per task: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --offline -- -D warnings`, the tests named in the task. Before the last commit of the branch: `cargo test --workspace --locked` and `scripts/golden.sh test`. Check and commit are chained with `&&`. The disk is tight: `CARGO_INCREMENTAL=0`, `cargo clean` after the full runs.
- The work is one GitHub pull request with the label `all-systems`, merged only after the user says yes. Never force-push.

## Review Focus

1. A LoD2 tile of 160 MB (the centre of Munich): it is streamed to the disk and read as a stream; it is never held in memory, and a file above 512 MB is refused with the name of the tile. (Task 8)
2. A map area across the border of the state (Neu-Ulm and Ulm, Passau and Austria): a tile the server does not have is silent when its centre lies outside Bavaria and a warning inside; the run goes on. (Task 7)
3. The server answers an HTML page or half a file instead of a TIFF, a zip or CityGML: the download is refused, nothing of it is cached, and an older cached file stays. (Tasks 6, 7, 8)
4. The `HEAD` that checks a cached file fails (timeout, 503): the run goes on with the cached file and says so; an offline run asks nothing at all. (Task 6)
5. A map area on the border of two Kreise: both files are read and an object both hold is kept once; a Kreis whose outline is within 100 m of the area is read too, so the simplified outlines never lose an object. (Task 8)

  ```rust

  /// and its polygons, each a list of closed rings of `[x, y]`, the outer ring first.
  pub struct ShapeRecord {
      pub fields: BTreeMap<String, String>,
  ```

### Task 6: Cached files named by the day they were changed

**Files:**
- Create: `crates/adapters/de/src/ldbv_files.rs`
- Modify: `crates/adapters/de/src/lib.rs` (module), `crates/freemapper-adapter-api/i18n/en/notes.ftl` and `…/de/notes.ftl` (one note)
- Test: unit tests in `ldbv_files.rs` with `MapFetcher` (its `modified` map answers `last_modified`) and `crate::clock::with_fixed`

**Interfaces:**
- Consumes: `Fetcher::last_modified`, `FetchMode`, `crate::clock::age_of`, `write_cache_file`.
- Produces:
  ```rust
  /// How long a 404 is believed, and a file of a server that sends no `Last-Modified`.
  pub const RECHECK_AFTER: Duration = Duration::from_secs(30 * 24 * 60 * 60);
  /// A file the agency publishes under a fixed address and replaces now and then.
  pub struct Published<'a> { pub dir: &'a Path, pub stem: &'a str, pub ext: &'a str, pub url: &'a str }
  pub enum Current {
      /// The cached file is the one to read.
      Cached(PathBuf),
      /// Download into `path`; once that is written, `older` can go.
      Fetch { path: PathBuf, older: Vec<PathBuf> },
      /// The server does not have the file.
      Missing,
  }
  pub fn current(
      fetcher: &dyn Fetcher,
      mode: FetchMode,
      file: &Published<'_>,
      progress: &mut dyn FnMut(Note),
  ) -> Result<Current, FetchError>
  /// The newest cached file of `stem`, without asking.
  pub fn cached(dir: &Path, stem: &str, ext: &str) -> Option<PathBuf>
  pub fn drop_older(older: &[PathBuf])
  ```
- File names: `<dir>/<stem>-<YYYYMMDD>.<ext>`; `<stem>-00000000.<ext>` when the server sends no `Last-Modified`; the 404 note is `<dir>/<stem>.missing`.
- Note `warning-file-check-failed` with `file` and `reason`. English: `could not check whether { $file } is still current ({ $reason }); using the cached file`. German: `Ob { $file } noch aktuell ist, ließ sich nicht prüfen ({ $reason }); die zwischengespeicherte Datei wird verwendet`.
- Rules: offline, the newest cached file, else `Missing` when the 404 note exists, else the error the tiles give offline (`offline and not cached: <url>; run \`freemapper fetch\` online`). Online: a 404 note younger than `RECHECK_AFTER` is `Missing` without a request; a 404 writes the note; a failed `HEAD` (not 404) with a cached file is `Cached` plus the note above, without one the error; a file named `-00000000` younger than `RECHECK_AFTER` is `Cached`, older is `Fetch` into the same path.
