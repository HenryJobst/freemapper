# Hamburg Adapter – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Maps in Hamburg get orthophoto, terrain, nDSM, ALKIS buildings and land use and OSM candidates, in
EPSG:25832 like Saxony-Anhalt.

**Architecture:** The second zone-32 provider, LGV Hamburg (`Provider::Lgv`).
- Rasters are fetched per area, like LVermGeo:
  - orthophoto from the WMS;
  - DGM1 and bDOM tiles (1 km GeoTIFF) read by HTTP range out of the statewide zips, mosaicked into
    `data/dgm1.tif` and `data/dom1.tif`.
- ALKIS comes from the OGC API (the LGB reader, parametrised by endpoint and CRS) with Hamburg's ASCII spellings
  normalised.
- A change of raster provider inside a zone drops the stored records, as a zone change does.

**Tech Stack:** no new crates (`zip` is not used for ranged reading; members are found in the central directory
and inflated with `miniz_oxide`).

**Spec:** `docs/superpowers/specs/2026-11-07-freemapper-design.md` §4.1. Verified sources (2026-11-07):
`docs/regions/hamburg-reference.md` (§n).

## Global Constraints

- **Region:**
  - `Region::Hamburg` (serde `"hamburg"`), boundary `assets/regions/hamburg.geojson` (`app:landesgrenze`, 25 m,
    in 25833), CRS `Utm32`, provider `Provider::Lgv`, object ids `DEHH…`.
  - OSM extract `europe/germany/hamburg-latest.osm.pbf` (54 MB), cached as `hamburg_<date>.osm.pbf`.
- **Orthophoto (§4.2):**
  - `https://geodienste.hamburg.de/wms_dop_zeitreihe_unbelaubt`, layer `dop_zeitreihe_unbelaubt`,
    `CRS=EPSG:25832`, with an explicit `TIME=2026`.
  - Never a closed-licence vintage (2023 leaf-off, 2022 leaf-on).
  - `WmsService` gains `extra: &'static str` for such parameters.
- **Flight date (§7):** zip `https://www.daten-hamburg.de/opendata/fernerkundung_luftbilder/dop_unbelaubt/DOP_unbelaubt_AdV-Metadaten_Hamburg.zip`,
  member `…/AdV-Metadaten_DOP_2026_unbelaubt_hh.csv`; the row `dop20rgbi_32_EEE_NNNN_1_hh_2026.tif` of the
  centre's 1 km tile, column `Aktualitaet` (`DD.MM.YYYY`).
- **DGM1/bDOM (§5, §6.1):**
  - Zips:
    - `https://archiv.transparenz.hamburg.de/hmbtgarchive/HMDK/dgm1_hh_2022-04-30_258334_snap_1.zip`;
    - `https://www.daten-hamburg.de/opendata/Digitales_Hoehenmodell_bDOM/dom1_hh_2022-11-21.zip`.
  - Members whose file name starts with `dgm1_32_EEE_NNNN_` / `dom1_32_EEE_NNNN_` and ends with `.tif`.
  - Read with `Fetcher::get_range`: the end of the file for the central directory (classic zip, < 4 GB), then the
    local header and the member, inflated (method 8) or stored (0).
  - The central directory and the members are cached under `cache/lgv/`.
  - Decoded with the GeoTIFF-tag reader, tiepoints rounded to mm; −9999 and −3.4e38 are NoData.
- **ALKIS (§8.1):**
  - OGC API `https://api.hamburg.de/datasets/v1/alkis_vereinfacht`, collections `GebaeudeBauwerk` and
    `NutzungFlurstueck`, `crs`/`bbox-crs` = 25832, `limit=10000`, `next` links.
  - Normalisation:
    - `gebnutzbez` `Gebaeude` → `Gebäude`;
    - `nutzart` through the table of §8.5 (matched on a transliterated lower-case key); unknown classes are kept.
- **Attribution:**
  `Freie und Hansestadt Hamburg, Landesbetrieb Geoinformation und Vermessung (LGV) <year>, dl-de/by-2-0, Daten geändert`.

## Review Focus

1. Hamburg buildings survive the kind rule, and land use drives out-of-bounds areas and paved areas (verges,
   Parkplatz).
2. A DGM tile at the state edge (−9999 outside) gives NaN, not deep pits in the hillshade.
3. Ranged zip reading: a server that ignores `Range` (200 with the whole file) → an error, not a 1.3 GB download.
4. A Saxony-Anhalt project moved to Hamburg (same zone) drops the LVermGeo records and files.
5. Existing regions are unchanged (requests, cache paths, attribution).
