# Saxony Adapter – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Maps in Saxony and across the Saxony/Brandenburg border get orthophoto, terrain, nDSM, ALKIS buildings and
land use, and OSM candidates, like Brandenburg maps.

**Architecture:** Regions become data.
- Each `Region` (Brandenburg, Berlin, Saxony) brings:
  - its official boundary (`assets/regions/*.geojson`);
  - its ALKIS source;
  - its raster provider (`Lgb` or `GeoSn`);
  - its OSM extract;
  - its attribution.
- ALKIS comes from every region the widened bbox touches, as for Berlin.
- Rasters and the tile products come from one provider: the one of the region containing the bbox centre (the
  *raster region*).
- OSM comes from the extracts of every touched region, merged by OSM id.

The later states (Saxony-Anhalt, Mecklenburg-Vorpommern, Thuringia, Hesse) then add a boundary, a provider and an
ALKIS source each.

**Tech Stack:** no new crates. GML is read with `quick-xml`; GeoTIFF with `tiff`; the WMS JPEG with `image`.

**Spec:** `docs/superpowers/specs/2026-11-07-freemapper-design.md` §4.1 and the later-work list.
Verified sources (2026-11-07): `docs/regions/saxony-reference.md` (cited as §n below).

## Global Constraints

- **Boundaries:**
  - All boundaries are simplified 25 m, EPSG:25833.
  - `brandenburg.geojson` comes from LGB `verwaltungseinheit` DE12 and has Berlin as a hole.
  - `saxony.geojson` comes from GeoSN `ave:VerwaltungsEinheit` DE14.
  - `berlin.geojson` stays as it is.
  - A region applies when its boundary intersects the bbox widened by 100 m.
  - The raster region is the region whose boundary contains the bbox centre; Berlin counts as an LGB region.
  - No raster region → `ProjectError::OutsideCoverage`. This replaces `LGB_COVERAGE`.
- **GeoSN tiles (§2.2):**
  - Tiles are 2 km with even south-west km corners.
  - File names: `dgm1_33EEE_NNNN_2_sn_tiff.zip` and `dom1_33EEE_NNNN_2_sn_tiff.zip`.
  - Zip members: `<stem>.tif` and `<stem>.tfw`, where `<stem>` = `dgm1_33EEE_NNNN_2_sn`.
  - Float32, NoData −9999.
- **GeoSN currency and URLs (§2.3, §2.4):**
  - Index: `https://geodienste.sachsen.de/ags-relay/ArcGISServer/guest/arcgis/rest/services/geosn/rest_geosn_downloadlinks/MapServer/<layer>/query`
    with layer 6 = DGM1 and layer 4 = DOM1.
  - Query parameters:
    `f=json&geometry=<xmin,ymin,xmax,ymax>&geometryType=esriGeometryEnvelope&inSR=25833&spatialRel=esriSpatialRelIntersects&outFields=Kachel,Download,Stand&returnGeometry=false`.
  - The envelope is the needed tiles' union shrunk by 1 m. Rows for tiles that are not needed are ignored.
  - `Kachel` `EEENNNN` gives the tile. The download URL is the row's `Download` field; without one, fall back to the
    current share URL.
  - Currency = published = the latest `YYYY-MM-DD` in `Stand`.
  - For offline use, the rows are merged into the cached `currency.json` of the product.
- **GeoSN orthophoto: WMS (§3.3).**
  - `https://geodienste.sachsen.de/wms_geosn_dop-rgb/guest`, layer `sn_dop_020`, WMS 1.3.0, `CRS=EPSG:25833`, JPEG.
  - Requested at 0.2 m on the template grid of map area + buffer, in pieces of at most 4000 × 4000 px, stitched
    together.
  - Stored as `data/orthophoto-wms.jpg` + `.jgw`.
  - Flight date from GetFeatureInfo on `sn_dop_020_info` (`INFO_FORMAT=text/plain`, text after `Datum:`).
  - **Ruling: WMS instead of the 230–270 MB tiles.** A single school map takes seconds instead of up to 1 GB at
    1 MB/s. Cost: the server re-encodes the JPEG, and the currency is the flight date text.
- **GeoSN nDSM:** DOM1 − DGM1 (`fill_from_dsm`). DOM1 is `Product::SaxonyDsm`, the laser DSM, which the glossary calls
  `Dsm`.
- **GeoSN ALKIS WFS (§6):**
  - `https://geodienste.sachsen.de/aaa/public_alkis/vereinf/wfs?SERVICE=WFS&VERSION=2.0.0&REQUEST=GetFeature&TYPENAMES=ave:GebaeudeBauwerk|ave:NutzungFlurstueck&SRSNAME=urn:ogc:def:crs:EPSG::25833&BBOX=E,N,E,N,urn:ogc:def:crs:EPSG::25833&COUNT=10000&STARTINDEX=k`.
  - Pages are fetched until a page returns fewer than 10000 features.
  - GML 3.2: features `ave:GebaeudeBauwerk` / `ave:NutzungFlurstueck` with child scalars and
    `geometrie/gml:MultiSurface/gml:surfaceMember/gml:Polygon/{exterior,interior}/gml:LinearRing/gml:posList` (E N).
  - Each feature becomes a GeoJSON feature with LGB properties. The names are already the same.
  - **Platz without `bez`** gets `bez = "ohne Unterart (Sachsen)"` and stays a candidate.
  - Up to 3 attempts per page. An answer that is not a `wfs:FeatureCollection` (an HTML page with status 400, or an
    ows exception) is an error.
- **OSM:** Geofabrik `europe/germany/sachsen-latest.osm.pbf` (≈270 MB) + `sachsen-updates/state.txt`, cached as
  `sachsen_<date>.osm.pbf`. Brandenburg and Berlin share `brandenburg`.
- **Attribution:**
  - The LGB line appears only when LGB tiles were fetched.
  - `Quelle: GeoSN, dl-de/by-2-0, Daten geändert` appears once GeoSN rasters, WMS or ALKIS data were fetched.
  - The sheet uses the same lines.

## Review Focus

   only (the other side may stay empty in the templates), OSM from both extracts with no duplicate ids.

   - HTML page with status 400 → clear error;
   - empty FeatureCollection → no buildings, with the warning;
   - an area over the 20 000 cap → paged with no truncation.
3. **Projects fetched before:** Brandenburg projects keep working, with no Saxony request and no new download (same
   cache paths, same extract file name).
4. **Offline Saxony runs:** use the cached GeoSN tiles, `currency.json`, the WMS image and the extract.
5. **A map area near the eastern edge (E > 500 km, Görlitz):** accepted. The old box check refused it.

- `fetch_project` takes its tile products from the raster region's provider:
