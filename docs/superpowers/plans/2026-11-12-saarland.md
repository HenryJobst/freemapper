# Saarland Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saarland becomes the twelfth state freemapper makes maps for, added on the adapter scheme of ADR 0082, and what it needed beyond its folder is written back as the result of gate E5.

**Architecture:** A manifest folder `crates/adapters/de/manifests/saarland/` declares identity, hosts, boundary, OSM extract, credit, the ALKIS WFS and the preview. The three rasters come from a new backend `lvgl` in `crates/adapters/de` (the pattern of Hamburg's `lgv`): the orthophoto from the free WMS, the terrain and surface model from the district zips of the LVGL's open-data share, read by range requests. The WFS reader learns to read attribute names in any case, so the cadastre needs no code of its own.

**Tech Stack:** Rust (workspace toolchain), `freemapper-manifest`, `freemapper-sources` (`wfs`, `zip_range`, `height_model`, `raster_fetch`), `freemapper-adapter-api`.

**Spec:** `docs/superpowers/specs/2026-11-10-region-adapters-design.md` (sections 3.3, 3.5, 3.8, 3.17, stage G rule) and `docs/regions/saarland-reference.md` (services, licences, probes of 2026-11-12). The gate itself is task E5 of `docs/superpowers/plans/2026-11-10-region-adapters.md`.

## Global Constraints

- Licence: only what the LVGL catalogue lists as `dl-de/by-2-0` is used. The two INSPIRE WCS services (`…/gdi-sl/inspireraster/inspirewcsel`, `…/inspirewcsoi`) are not asked; their own capabilities still say a contract is needed.
- The products the LVGL charges for (bDOM20, DOM025, the "Premium" orthophoto years) are left out on purpose. The user wants to wait for a concrete request before anything like it is built; that would be an opt-in of its own with an ADR.
- Credit, exactly: `© GeoBasis DE/LVGL-SL {year}, dl-de/by-2-0, Daten geändert` (source note of the records plus the changed-data mark the other states carry).
- Hosts, exactly: `geoportal.saarland.de`, `www.shop.lvgl.saarland.de`. Every request of the state stays on them (ADR 0106).
- Adapter id `saarland`, provider `lvgl`, cache folder `lvgl`, CRS EPSG:25832, object-id prefix `DESL`, Geofabrik path `europe/germany/saarland`, names `Saarland` in both languages, agency `LVGL`.
- Requests carry the fixed `User-Agent` and nothing personal. No e-mail address in any request, file or commit.
- Source and technical docs English, user docs German and English, German text says "Bundesland".
- The golden net of the eleven states does not change except G1 and G2 files that list every adapter; a commit that changes them carries `Golden-Bless: Saarland added` and is not a `refactor(` commit.
- House rules for a new state: example project, manual row, README row in both languages, changelog in both languages, ADR.
- Verification per task: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --offline -- -D warnings`, the tests named in the task; before the last commit the full detached run (workspace, stub tests, `scripts/golden.sh test`). Check and commit are chained with `&&`.

## Review Focus

1. A 1 km tile that two district zips both hold (a tile on a district border): the first one found is used, the map is the same whichever it is, and it is fetched once.
2. The share is renamed or a zip is replaced (new survey year): no tile is found; the error names the archive folder and says the archive may have been renamed, and nothing is half-written.
3. A map area that reaches into France, Luxembourg or Rhineland-Palatinate: tiles outside Saarland are absent from every zip; they stay empty without a warning, and a missing tile inside Saarland is a warning.
4. The server answers a range request with the whole file (1 GB): the fetch stops with the range error before the body is read.
5. The feature info of the orthophoto has no `Aktualisierung` row, or is not HTML: the orthophoto is stored without a flight date and the fetch goes on.

### Task S2: The raster backend `lvgl`

**Files:**
- Create: `crates/adapters/de/src/lvgl.rs`
- Modify: `crates/adapters/de/src/lib.rs` (module), `crates/adapters/de/src/states/mod.rs` (`Agency::Lvgl`: id `lvgl`, terrain source `lvgl-dgm1`, per-area kind, CRS 25832; `backend_name` gives `lvgl`), `crates/adapters/de/src/states/rasters.rs` (the arm)
- Test: `crates/adapters/de/src/lvgl.rs` (unit tests with `MapFetcher` and archives built by `freemapper_sources::zip_range::test_support::archive`)

**Interfaces:**
- Consumes: `freemapper_sources::zip_range::{read_directory_bytes, parse_directory, find_member, cached_member, refused}`, `freemapper_sources::raster_fetch` (the WMS orthophoto fetch Hamburg uses), `freemapper_adapter_api::rasters::{RasterBackend, ProviderInfo, RasterKind}`.
- Produces:
  - `pub const WMS: WmsService` (url `https://geoportal.saarland.de/freewms/dop2025`, layer `sl_dop20_rgb`, EPSG:25832, JPEG).
  - `pub const SHARE: &str = "https://www.shop.lvgl.saarland.de/cloud/public.php/dav/files/NK8ndP55qAqGEZD"`.
  - `pub const DISTRICTS: [&str; 6] = ["MZG", "NK", "SB", "SLS", "SPK", "WND"]`.
  - `pub enum Model { Dgm1, Dom1 }` with `archive_url(self, district: &str) -> String` (`{SHARE}/OD_DGM1_2025_tif_LK/DGM1_tif_{district}_EPSG-25832_Entstehung-2025.zip`, `OD_DOM1_2025_tif_LK/DOM1_tif_…`), `release(self) -> &'static str` (`dgm1-2025`, `dom1-2025`), `date(self) -> &'static str` (`2025`), `label(self)` (`terrain model (LVGL DGM1 2025)`, `surface model (LVGL DOM1 2025)`), `tile_cache_file(self, cache, tile) -> PathBuf` (`lvgl/<dgm1|dom1>/<release>/<prefix>_32_<EEE>_<NNNN>_.tif`).
  - `pub fn flight_date(fetcher: &dyn Fetcher, bbox: &BoundingBox) -> Option<String>`: `GetFeatureInfo` on `sl_dop_info` at the centre of `bbox`, `INFO_FORMAT=text/html`; the cell after `Aktualisierung` when it reads `DD.MM.YYYY`.
  - `pub fn fetch_model(fetcher, cache, mode, model, bbox, root, out) -> Result<Vec<TileId>, FetchError>`: as `lgv::fetch_model`, over the six archives. The directories are cached as `lvgl/<model>/<release>/directory-<district>.bin`. A tile is looked for in the directories in the order of `DISTRICTS`; a directory is read only when the tiles before it left a tile unfound. Returned are the tiles inside Saarland that no archive holds.
  - `pub struct LvglBackend` implementing `RasterBackend` (`provider()` with id `lvgl`, cache dir `lvgl`, terrain source `lvgl-dgm1`, `RasterKind::PerArea`; `fetch` = orthophoto, terrain, surface as Hamburg does, the surface model only a template whose failure is a warning; `estimate` as the other per-area states).

  - `directories_and_tiles_come_from_the_cache_offline`: fetch online, then offline with an empty fetcher; assert equal output and zero requests.
  - `no_tile_at_all_names_the_archive_folder`: every directory without the tiles; assert the error text contains `OD_DGM1_2025_tif_LK` and `may have been renamed`, and that `out` does not exist (Review Focus 2).

  - `a_range_answered_with_the_whole_file_is_refused`: a fetcher that answers ranges with `RangeIgnored`; assert the error is that one (Review Focus 4).
  - `the_flight_date_is_the_update_row_of_the_feature_info`: the HTML recorded on 2026-11-12 gives `10.05.2025`; an answer without the row and a plain-text answer give `None` (Review Focus 5).
  - `the_backend_names_its_provider`: id `lvgl`, cache dir `lvgl`, terrain source `lvgl-dgm1`, per-area.
